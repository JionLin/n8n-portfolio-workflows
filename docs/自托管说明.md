# Self-hosting n8n for these workflows

Two ways to run n8n: Docker Compose (recommended, included in this repo), or a native Node.js install.

## Option A: Docker Compose

Requirements: Docker Engine with Compose v2. Linux also needs Docker 20.10+ for `host-gateway`.

```bash
cp .env.example .env
```

Edit `.env`:

1. Set `N8N_ENCRYPTION_KEY` to a random value, for example `openssl rand -hex 32`. n8n encrypts saved credentials with this key. If you lose it, the credentials cannot be decrypted. Keep it out of git.
2. Fill in the workflow variables you need (see the table below).

Start n8n:

```bash
mkdir -p n8n-data
docker compose up -d
docker compose logs -f n8n
```

Open http://localhost:5678 and create the owner account on first visit.

Stop or update:

```bash
docker compose down
docker compose pull && docker compose up -d   # after bumping the image tag in docker-compose.yml
```

Image tag: `docker-compose.yml` pins `docker.n8n.io/n8nio/n8n:2.44.6`, the version the workflows were imported into for testing. Check the tag exists in your registry before pinning, and update it deliberately.

### What the compose file does

| Setting | Why |
| --- | --- |
| Port `127.0.0.1:5678` | Only reachable from this machine. Change it only if you add authentication or a reverse proxy. |
| `env_file: .env` | Passes the variables below to n8n and to `$env` expressions in workflows. |
| `N8N_BLOCK_ENV_ACCESS_IN_NODE=false` | The workflows read `$env.*` in expressions and in the Code node. |
| `N8N_SECURE_COOKIE=false` | Plain HTTP on localhost. Set to `true` behind HTTPS. |
| `WEBHOOK_URL=http://localhost:5678/` | Base URL shown in webhook addresses. Set it to your public URL when exposed. |
| `./n8n-data` volume | Keeps workflows, credentials and executions across restarts. Git-ignored. |
| `host.docker.internal:host-gateway` | Lets n8n reach a SupportPilot backend running on the host. |

## Environment variables

| Variable | Used by | Example |
| --- | --- | --- |
| `N8N_ENCRYPTION_KEY` | n8n core | random hex string |
| `GENERIC_TIMEZONE` | n8n core | `UTC` |
| `LEAD_SHEET_ID` | 01 Google Sheets node | ID from the sheet URL |
| `SLACK_CHANNEL` | 01 Slack node | `'#leads'` |
| `NOTIFY_EMAIL` | 01 and error-handler Gmail nodes | `you@example.com` |
| `LLM_BASE_URL` | 02 HTTP Request node | `https://api.openai.com/v1` or any compatible base URL |
| `LLM_API_KEY` | 02 HTTP Request node | your key, in `.env` only |
| `LLM_MODEL` | 02 HTTP Request node | your model name |
| `GMAIL_LABEL_IDS_JSON` | 02 Parse and label steps | `'{"billing":"Label_123"}'` |
| `SUPPORTPILOT_BASE_URL` | 03 HTTP Request node | `http://host.docker.internal:8000` |

Quote values that contain `#`, JSON or spaces, as `.env.example` does.

## Credentials to create in the n8n UI

Credentials are never stored in the JSON files. Create them under **Credentials** in n8n, then open each node and select them:

- Google Sheets OAuth2 (workflow 01)
- Slack API (workflow 01)
- Gmail OAuth2 (workflows 01 and 02)

Each import contains placeholder credential IDs. n8n shows the node as needing a credential until you select one.

## Option B: native Node.js

n8n 2.x requires Node.js 24 or later.

```bash
npx n8n
```

Set the same variables in your shell or in a `.env` file before starting. Point `SUPPORTPILOT_BASE_URL` at `http://127.0.0.1:8000` when n8n runs on the same machine as the backend.

## Run the portfolio workflows

The three workflows do not use n8n Assistant or its sandbox. Skip the **Add a code sandbox** step in the Assistant wizard, or close it. The compose file runs only n8n; it has no sandbox services.

### 1. Import

In **Workflows → Import from File**, import:

| File | Notes |
| --- | --- |
| `workflows/01-lead-capture/lead-capture.json` | Webhook intake. |
| `workflows/01-lead-capture/error-handler.json` | Then select it under the lead-capture workflow's **Settings → Error workflow**. Manual test runs do not trigger it. |
| `workflows/02-email-ai-triage/email-ai-triage.json` | Has a Manual Trigger for the sample email and a Gmail trigger for live mail. |
| `workflows/03-supportpilot-http/supportpilot-http.json` | Needs a running SupportPilot backend for a full request. |

### 2. Credentials

Create credentials only for the services you use (see [Credentials to create in the n8n UI](#credentials-to-create-in-the-n8n-ui)). Workflow 03 needs none. Workflow 02's sample run reaches the LLM and parse steps without Gmail; the Gmail nodes stop on the sample email.

### 3. Environment

```bash
cp .env.example .env
```

Set the values for the workflows you test (see [Environment variables](#environment-variables)). After editing `.env`, run `docker compose up -d` again so the container is recreated with the new values. `docker compose restart` does not reread `env_file`.

For SupportPilot on the same host as Docker, keep `SUPPORTPILOT_BASE_URL=http://host.docker.internal:8000`. Check the backend from the host first:

```bash
curl http://127.0.0.1:8000/api/health
```

### 4. Test without external services

Each webhook has two URLs. The **test** URL works while you click **Listen for test event** in the Webhook node; it uses the `/webhook-test/` prefix. The **production** URL uses `/webhook/` and works only after the workflow is activated. The examples below use the production path, so activate first or switch to the test path.

Workflow 01, invalid lead (returns `400` before any Google, Slack or Gmail node):

```bash
curl -X POST http://localhost:5678/webhook/lead-capture \
  -H "Content-Type: application/json" \
  -d '{"name":"","email":"not-an-email"}'
```

Expected: `{"status":"rejected","reason":"name_or_email_invalid"}`

Workflow 03, empty message (returns `400` before the SupportPilot request):

```bash
curl -X POST http://localhost:5678/webhook/ask-supportpilot \
  -H "Content-Type: application/json" \
  -d '{"message":""}'
```

Expected: `{"error":"message_required"}`

Open the workflow's **Executions** tab to see which nodes ran for each request.

### 5. Test with real results

- **Workflow 02:** open **Manual Trigger (sample email)**, then **Execute workflow**. Inspect **Parse Classification**. This needs `LLM_BASE_URL`, `LLM_API_KEY` and `LLM_MODEL`.
- **Workflow 03, full path:** with SupportPilot running, use **Health Check (manual)** to confirm reachability, then POST `workflows/03-supportpilot-http/fixtures/webhook-input.example.json`. A valid request returns the AgentReply JSON with `conversation_id`.
- **Workflow 01, valid lead:** needs a Google Sheets credential and a `Leads` tab. Without a credential, the Sheets node fails and n8n returns `500`, which is expected.

The fastest end-to-end demo with no third-party accounts is workflow 03 with SupportPilot running locally.

### 6. Activate

Activate a workflow after its test runs pass. Workflow 02 contains a Gmail trigger, so attach Gmail OAuth2 before activating it.

## Optional: n8n Assistant sandbox

Not required for workflows 01, 02 or 03. Skip this section unless you want n8n's built-in Assistant.

Assistant needs a model API key (Anthropic, OpenAI or OpenRouter) and a sandbox. The official guide is [Set up n8n Assistant](https://docs.n8n.io/deploy/host-n8n/configure-n8n/set-up-ai-assistant). Per that guide, `n8n-sandbox` suits local development and testing, and Daytona is the managed option recommended for production.

| Sandbox | Service URL | API key | Where it comes from |
| --- | --- | --- | --- |
| n8n Sandbox (self-hosted) | `http://sandbox-api:8080`, only if n8n and the sandbox API share a Docker network | A secret you choose. It must match `SANDBOX_API_KEYS` on the sandbox API and `N8N_SANDBOX_SERVICE_API_KEY` on n8n. | The sandbox stack (`sandbox-certs`, `sandbox-api`, `sandbox-runner-1`) is not in this repo. Follow the [Docker Compose install guide](https://docs.n8n.io/deploy/host-n8n/install-options/install-using-docker-compose). |
| Daytona (paid, hosted) | Not used by the self-hosted sandbox. The official Daytona setup uses `DAYTONA_API_URL` (default `https://app.daytona.io/api`). | `DAYTONA_API_KEY` from your Daytona account | [Set up n8n Assistant, Setup 3](https://docs.n8n.io/deploy/host-n8n/configure-n8n/set-up-ai-assistant) |

Self-hosted `n8n-sandbox` environment variables, from the official guide:

```bash
N8N_INSTANCE_AI_SANDBOX_ENABLED=true
N8N_INSTANCE_AI_SANDBOX_PROVIDER=n8n-sandbox
N8N_SANDBOX_SERVICE_URL=http://sandbox-api:8080
N8N_SANDBOX_SERVICE_API_KEY=replace-with-your-own-secret
```

On the sandbox API container, set the same secret in `SANDBOX_API_KEYS`. Keep both in `.env` or your secret store, not in git.

Notes:

- The Service URL must be reachable from the n8n container. `sandbox-api` resolves only on the Compose network that contains both services.
- The API key is not a model provider key. It is a shared secret between n8n and the sandbox API.
- Check the sandbox with `curl http://<sandbox-api-host>:8080/healthz`. Expected: `{"status":"ok"}`.
- Set the model key with `N8N_INSTANCE_AI_MODEL_API_KEY`. The guide's default model is `anthropic/claude-opus-4-8`.
- Settings → Agents → Shared sandbox is where the sandbox connection is configured in the UI. Agents and Assistant share it.
- To remove Assistant entirely, the official guide documents `N8N_DISABLED_MODULES=instance-ai`. Check that it applies to your n8n version before relying on it. This repo does not set it.

This repo has not run a sandbox or Assistant stack. The steps above come from the official docs.

## Exposing webhooks

The webhook paths are:

- `/webhook/lead-capture` (01)
- `/webhook/ask-supportpilot` (03)

If n8n is reachable from the internet, anyone who can reach these URLs can trigger them. Before exposing n8n:

- Put it behind a reverse proxy with HTTPS and set `WEBHOOK_URL` to the public URL.
- Add authentication to the webhook nodes (Header Auth or a similar check), or restrict access at the proxy.
- Set `N8N_SECURE_COOKIE=true`.

## Backups

Back up `n8n-data/` and keep `N8N_ENCRYPTION_KEY` with it. Restoring the folder without the key leaves the credentials unreadable.
