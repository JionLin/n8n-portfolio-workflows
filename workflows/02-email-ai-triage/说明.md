# 02 Email AI triage

Classifies incoming email with an OpenAI-compatible Chat Completions endpoint, then routes it. Emails that need a reply get a Gmail **draft** (never sent). Every email with a mapped category gets a Gmail label.

Files:

- `email-ai-triage.json`: the workflow.
- `fixtures/sample-email.json`: synthetic email for the Manual Trigger.
- `fixtures/expected-parse-output.example.json`: example of the structured output shape. It is hand-written from the schema, not captured from a model run.

## Flow

1. **New Inbox Email (Gmail)** polls unread INBOX messages every minute. **Manual Trigger (sample email)** feeds `sample-email.json` instead.
2. **Normalize Email** keeps the fields needed for triage and truncates the body to 4000 characters.
3. **Classify with LLM** calls `POST {LLM_BASE_URL}/chat/completions` with `response_format: json_object` and `temperature: 0`.
4. **Parse Classification** validates the reply. Anything malformed becomes category `other` with `needs_human_review: true`, and no draft is created.
5. **Needs Reply?** → **Create Draft Reply (not sent)** creates a Gmail draft in the same thread.
6. **Has Label Mapping?** → **Apply Triage Label** adds the Gmail label ID for the category.

## Output schema

```json
{
  "category": "billing | technical_support | sales_inquiry | spam | other",
  "priority": "low | medium | high",
  "needs_reply": true,
  "suggested_label": "same values as category",
  "draft_reply": "string, for human review",
  "summary": "string, at most 25 words"
}
```

The parse step does not use `suggested_label`. It maps `category` to a Gmail label ID using `GMAIL_LABEL_IDS_JSON`.

## Environment variables

| Variable | Purpose |
| --- | --- |
| `LLM_BASE_URL` | Base URL of any OpenAI-compatible API, for example `https://api.openai.com/v1`. |
| `LLM_API_KEY` | Bearer token. Stored only in your local `.env`. |
| `LLM_MODEL` | Model name for that endpoint. |
| `GMAIL_LABEL_IDS_JSON` | JSON object mapping each category to a Gmail label ID, for example `{"billing":"Label_123"}`. |

## Run the demo

1. Set the variables above in `.env`, then restart n8n.
2. Open the workflow and click **Manual Trigger (sample email)**, then **Execute workflow**.
3. Inspect **Parse Classification**. The Gmail nodes need a real message ID and mailbox, so they fail on the synthetic sample. That is expected.

To go live, attach Gmail OAuth2 credentials and activate the workflow. The Gmail trigger then processes real unread mail.

## Limitations

- Not every provider supports `response_format`. If it is rejected, remove that field from the JSON body.
- Labels are applied by ID. Gmail label names cannot be used directly.
- Model output is untrusted. Drafts are for review. Nothing is sent automatically.

## Verification

Tested against a local stub LLM: the request body and bearer header were correct, and the parse step produced the expected structured output. The Gmail draft node stopped on the placeholder credential. The Gmail trigger, label action and real mailbox were not exercised.
